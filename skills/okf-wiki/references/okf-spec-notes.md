# OKF v0.1 — reference notes

Summary of the spec published by Google Cloud (June 2026) and of the choices made by this skill.
Spec and reference implementations: https://github.com/GoogleCloudPlatform/knowledge-catalog/tree/main/okf

## What OKF is

An open, vendor-neutral specification that formalizes the LLM-wiki pattern into a portable format. It is not a service, an SDK or a runtime: it is a **format**. An OKF bundle is:

- **markdown only** — readable in any editor, renderable on GitHub, indexable by any search engine
- **files only** — shippable as a tarball, hostable in a git repo, mountable on any filesystem
- **YAML frontmatter only** — for the small set of structured fields that must be queryable

The value of the format comes from how many parties speak it, not from who owns it.

## The model

A **bundle** is a directory of markdown files representing **concepts**. A concept is anything you want to capture: a table, a dataset, a metric, a runbook, an API — and, for this skill, a document, an entity, a notion, a synthesis.

**One concept = one file. The file path is its identity.**

Concepts link to each other with ordinary markdown links. The result is a **graph** of relations richer than the parent/child hierarchy the filesystem implies — and that is what distinguishes an OKF bundle from a folder of notes.

## The three design principles

1. **Minimally prescriptive.** OKF requires exactly one thing from every concept: the `type` field. Which types exist, which other fields to include, what sections the body has — all of it is left to the producer. The spec defines the interoperability surface, not the content model.
2. **Producer/consumer independence.** Whoever writes the knowledge is separate from whoever consumes it. A hand-written bundle can be read by an agent; one generated by a pipeline can be browsed in a viewer; one synthesized by an LLM can be queried by another. The format is the contract, the tools at either end are replaceable.
3. **A format, not a platform.** No tie to a cloud, a database, a model provider or an agent framework. It will never require a proprietary account to be read, written or served.

## Frontmatter fields

| Field | Status | Notes |
|---|---|---|
| `type` | **required** | the spec's only hard requirement |
| `title` | conventional | human-readable title |
| `description` | conventional | one sentence |
| `resource` | conventional | URI/path of the described resource |
| `tags` | conventional | list |
| `timestamp` | conventional | ISO 8601 |

`sources` is an extension of this bundle, not of the spec: it tracks the document pages a page derives from. Extensions are allowed — they stay readable by consumers that do not know them, which simply ignore them.

## Reserved names

- `index.md` — a directory's catalogue, for *progressive disclosure*: an agent navigating the hierarchy reads the index before descending into the pages. At moderate scale (~100 sources, a few hundred pages) this replaces embedding retrieval.
- `log.md` — the chronological history of changes.

Both are optional per the spec. This skill treats them as mandatory: without an index the wiki is not navigable by an agent, and without a log the story of how it grew is lost.

## Choices specific to this skill

Constraints this skill adds on top of OKF, to orient the format towards documents:

- Default categories `documents/`, `entities/`, `concepts/`, `syntheses/` — adaptable to the domain at bootstrap.
- `raw/` holds the immutable sources and **is not part of the OKF bundle**: it must be excluded from export and validation.
- Every path a page writes — markdown links and the `resource` / `sources` frontmatter fields — is **relative to that page**, never absolute: `../entities/acme-spa.md`, not `/entities/acme-spa.md`. The spec does not mandate a form; relative paths are what keeps a bundle browsable after it is moved, rendered on GitHub or opened in an editor.
- Every substantive claim in a document page carries a reference to its position in the source (section, page, clause). That is what makes the wiki verifiable rather than merely plausible.
- Contradictions are not resolved by overwriting: they are recorded under `## Open points` with the source and date of both versions.

## Ecosystem

Google published three reference implementations: an enrichment agent that generates OKF concepts from BigQuery datasets, a static HTML viewer that renders a bundle as an interactive graph in a single self-contained file, and three navigable example bundles (GA4 e-commerce, Stack Overflow, Bitcoin). They are avowedly proofs of concept: nothing in the format requires that specific agent or that specific UI.

v0.1 is a starting point, versioned and designed to grow backwards-compatibly.
